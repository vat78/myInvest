# myInvest

Локальное приложение для учёта инвестиций. Стек: Go, Wails, SQLite,
Svelte + TypeScript, Apache ECharts. Отвечай кратко и по делу.

## Архитектура

- Сначала читай `docs/architecture.md` и спецификацию соответствующей фичи.
- Разделяй предметную логику, сценарии приложения и адаптеры хранения/UI.
- Создавай модули в `internal/` по бизнес-возможностям только при реализации.
  Не создавай пустые Go-пакеты, `go.mod` или Wails boilerplate заранее.
- Предметная логика не зависит от Wails, SQLite, фронтенда или графиков.
- Wails — тонкий адаптер: проверяет входные DTO и вызывает сценарии приложения.
- SQLite доступна через слой хранения. SQL и транзакции не попадают в UI.
- Svelte отвечает за отображение и ввод; финансовые расчёты выполняются в Go.
- ECharts получает подготовленные данные и не служит источником финансовых итогов.
- Не добавляй библиотеки или инфраструктуру без необходимости. Значимые решения
  фиксируй в `docs/decisions/`, требования и критерии приёмки — в `docs/features/`.

## Финансовая точность

- Не используй `float32`, `float64` и JavaScript `number` для денег, цен,
  количества бумаг, курсов, комиссий и финансовых расчётов.
- Используй точные десятичные значения либо целые числа с явно заданным масштабом.
  Конкретное представление и библиотеку выбери отдельным архитектурным решением.
- Передавай точные значения между Go и TypeScript строками. В SQLite храни
  десятичные строки либо масштабированные INTEGER; не используй REAL и не полагайся
  на NUMERIC affinity или SQL-агрегации для точной десятичной арифметики.
- Денежное значение всегда связано с валютой; не складывай разные валюты без
  явной конвертации с указанными курсом, источником и датой.
- Правила округления, масштаб и момент округления должны быть явными и проверяемыми.
  Не округляй промежуточные вычисления автоматически.
- Учитывай комиссии, знаки операций и дробные количества согласно спецификации.
  Метод расчёта себестоимости и доходности не выбирай молча.
- Храни время и дату операции с явной семантикой; не подменяй календарную дату
  произвольным часовым поясом. Результаты должны воспроизводиться из исходных данных.
- Преобразование в `number` разрешено только на границе графика для визуализации;
  такие значения нельзя использовать для расчётов, хранения или точных подписей.

## Данные и миграции

- Изменения схемы оформляй последовательными версионированными SQL-миграциями
  в `migrations/`. Не изменяй уже применённые миграции.
- Многошаговые изменения данных выполняй в транзакции. Используй параметризованный SQL,
  ограничения целостности и включай foreign keys для каждого соединения.
- Не удаляй пользовательскую БД и не выполняй разрушительные миграции без запроса.
  Перед миграциями существующей БД предусмотрены резервная копия и обработка ошибок.
- Не добавляй в Git реальные портфели, базы данных, ключи или другие секреты.

## Тестирование и рабочий процесс

- Для финансовых расчётов нужны табличные unit-тесты с точными ожидаемыми значениями:
  дроби, комиссии, округление, нули, допустимые отрицательные значения, разные валюты.
- Для хранения и миграций нужны интеграционные тесты на временной SQLite-БД,
  включая ограничения и откат транзакций. Не используй рабочую БД пользователя.
- Тестируй поведение и критерии приёмки, а не внутреннюю реализацию.
- После появления Go-кода запускай `gofmt`, `go test ./...` и `go vet ./...`.
  Для фронтенда запускай проверку TypeScript/Svelte, тесты и сборку по скриптам
  реально созданного `package.json`; не придумывай отсутствующие команды.
- Для изменений только документации достаточно проверить текст и Git diff.
- Не создавай коммит, не отправляй изменения и не публикуй приложение без запроса.
