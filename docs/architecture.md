# Архитектура myInvest

## Назначение и состояние

Локальное desktop-приложение для учёта инвестиций. Данные хранятся локально в SQLite.
Технологический ориентир: Go + Wails, Svelte + TypeScript, Apache ECharts.
Реализована техническая оболочка по спецификации 000: Wails 2.15.0, Go 1.27.2,
Svelte 5/TypeScript 6, Vite 8 и SQLite. Реализован справочник валют и ручные
курсы по спецификации 001; правила представлены в [ADR 0003](decisions/0003-currency-rates.md).
Версии и решения закреплены в [ADR 0001](decisions/0001-app-bootstrap.md).

## Границы ответственности

```text
Svelte UI → Wails bindings / DTO → сценарии приложения → предметная логика
                                       ↓
                              интерфейсы хранения
                                       ↑
                                SQLite-адаптер

Подготовленные данные → Apache ECharts
```

Предметная логика содержит финансовые правила и не зависит от UI и базы данных.
Сценарии приложения координируют операции, валидацию и границы транзакций.
SQLite-адаптер реализует необходимые интерфейсы хранения. Интерфейсы определяются
по потребностям сценариев, без универсального репозитория заранее.
Wails связывает UI с Go через тонкий слой DTO; SQL и финансовые расчёты остаются в Go.

Код группируется по бизнес-модулям внутри `internal/`, а границы слоёв выделяются
по мере необходимости. Модули и API создаются только под согласованные фичи.
Возможные области — операции, инструменты, портфели и оценка; это ориентиры,
а не готовые пакеты или согласованная модель данных.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `AGENTS.md` | Правила архитектуры, точности и проверки изменений |
| `docs/architecture.md` | Общая архитектура и границы модулей |
| `docs/decisions/` | Значимые архитектурные решения (ADR) |
| `docs/features/` | Спецификации фич и критерии приёмки |
| `internal/` | Go-код предметной логики, сценариев и адаптеров |
| `frontend/` | Svelte/TypeScript UI и интеграция ECharts |
| `migrations/` | Версионированные SQL-миграции |

`main.go` запускает Wails и встраивает frontend/dist. `app.go` управляет
инициализацией/закрытием хранилища и предоставляет технический `GetAppInfo`.
`internal/storage/sqlite` управляет общим пулом соединений SQLite и миграциями.
`migrations/embed.go` встраивает SQL-файлы в собранное приложение.
Wails bindings находятся в `frontend/wailsjs` и обновляются при сборке.
Весь Go-код валют сгруппирован в `internal/currency`:

```text
internal/currency/
    domain.go, domain_test.go           — предметные проверки и типы
    service.go, service_test.go         — сценарии и интерфейс хранения
    desktop/api.go, api_test.go         — Wails API и строковые DTO
    sqlite/repository.go, repository_test.go — SQL-запросы и интеграционные тесты
```

Адаптеры зависят от модуля валют, а предметные проверки и сценарии не зависят
от адаптеров. `app.go` подключает компоненты и обеспечивает готовность хранилища
и защиту операций от параллельного закрытия БД; `main.go` регистрирует отдельный
валютный API в Wails. Общий пул принадлежит `internal/storage/sqlite.Store`,
валютный репозиторий получает его без права управлять жизненным циклом.
См. [ADR 0004](decisions/0004-feature-module-layout.md).

## Финансовые данные

Все вычисления выполняются с точными десятичными значениями или целыми числами
с заданным масштабом. Деньги имеют валюту; количество, цена и курс имеют явно
определённую точность. DTO передают эти значения строками. SQLite хранит их как
TEXT или масштабированный INTEGER; выбор фиксируется в ADR до реализации схемы.
REAL и неявные преобразования в дробные числа для финансовых данных запрещены.

Политика округления, метод себестоимости, правила доходности, конвертация валют
и семантика дат определяются спецификациями и тестами. ECharts может использовать
приближённые числа для координат графика, но точные суммы и подписи берутся
из исходных данных. UI не пересчитывает финансовые итоги самостоятельно.

## Хранение

База пользователя располагается в каталоге данных приложения вне репозитория.
Используется modernc.org/sqlite 1.58.0, WAL и synchronous=FULL.
На macOS путь — `~/Library/Application Support/myInvest/myinvest.sqlite3`,
на Windows — `%LOCALAPPDATA%\myInvest\myinvest.sqlite3`, на Linux —
`$XDG_DATA_HOME/myInvest/myinvest.sqlite3` (по умолчанию `~/.local/share`).
Абсолютный `MYINVEST_DATA_DIR` позволяет изолировать тестовые запуски.
Опциональный `MYINVEST_PORTABLE=1` размещает БД рядом с `.app` на macOS,
а для отдельного бинарника — в его каталоге. `MYINVEST_DATA_DIR` имеет приоритет;
системный каталог остаётся по умолчанию. См. [ADR 0002](decisions/0002-portable-storage.md).
Связанные изменения атомарны; внешние ключи включаются для каждого соединения.
Миграции имеют устойчивый порядок, учёт применённых версий и не переписываются
после применения. Для существующей БД предусматриваются резервная копия
через SQLite VACUUM INTO и безопасное завершение при ошибке.
Версии, имена и SHA-256 записываются в schema_migrations атомарно с SQL;
неизменность истории проверяется перед обновлением. Миграция 0002 создаёт
`currencies` и `currency_rates`: точные курсы TEXT, календарная дата и
упорядоченная пара валют с внешними ключами. При ручном сохранении прямой и
обратный курсы обновляются атомарно. Обратный рассчитывается в Go через
точное целочисленное деление (`math/big.Int`) с округлением half up до 18 знаков
после запятой; прямой курс не округляется. См. [ADR 0005](decisions/0005-inverse-currency-rates.md).

## Как развивать проект

1. Согласовать фичу в `docs/features/`: цель, поведение, входные данные,
   финансовые правила, ошибки и проверяемые критерии приёмки.
2. Зафиксировать значимые решения в `docs/decisions/`: контекст, решение,
   альтернативы и последствия. Использовать последовательные номера файлов.
3. Реализовать минимально нужные модули и миграции, добавить тесты поведения.
4. Проверить Go и фронтенд командами из `AGENTS.md`, обновить документацию.

Запуск и проверки описаны в [README](../README.md). Реализованный
[справочник валют](features/001-currency-directory.md) использует точные строки
без округления для ручного ввода. Обратный курс имеет явно заданное округление;
представление и правила остальных финансовых расчётов выбираются отдельно.

## Портфели

Реализованы просмотр, создание и редактирование по спецификации 002.
`internal/portfolio` содержит типы, проверки названия и календарной даты,
сценарии чтения/создания/редактирования и интерфейс хранения. Подпакеты
`sqlite` и `desktop` реализуют SQL и отдельный Wails `PortfolioAPI`.
Миграция 0003 создаёт `portfolios`: идентификатор INTEGER передаётся в DTO
строкой, `name_key` формируется в Go через TrimSpace/ToLower и защищён UNIQUE.
Валюта ссылается на currencies и при редактировании проверяется в Go; UPDATE
не изменяет её и дополнительно проверяет совпадение в WHERE. Каждое сохранение
выполняется одним атомарным SQL-запросом. Дата хранится и передаётся календарной
строкой без часового пояса. Поля формы получают структурированные ошибки;
ошибки хранения скрывают технические детали. `PortfolioManager.svelte`
отвечает за меню, модальные окна, загрузку, повтор чтения и возврат фокуса.

## Денежные операции

Реализована спецификация 003. `internal/cashflow` содержит точные суммы,
расчёт остатка и справочного курса, проверки и сценарии журнала. Адаптеры
`sqlite` и `desktop` обеспечивают транзакции и отдельный Wails `CashFlowAPI`.
Миграция 0004 создаёт `cash_flows`; суммы — TEXT, устойчивые идентификаторы
INTEGER с AUTOINCREMENT передаются строками. Остаток выводится из снимка
истории в Go; справочные курсы не участвуют. Арифметика math/big и округление
курса описаны в [ADR 0006](decisions/0006-portfolio-cash-flows.md).
Отрицательный остаток разрешён с предупреждением; дополнительных ограничений
дат нет. `CashFlowManager.svelte` показывает выбор портфеля, остаток, журнал,
формы изменения и подтверждение удаления. После сохранения портфеля список
выбора обновляется. Суммы и курс UI получает строками из Go; устаревшие ответы
чтения и предварительного расчёта курса отбрасываются.
