# Архитектура myInvest

## Назначение и состояние

Локальное desktop-приложение для учёта инвестиций. Данные хранятся локально в SQLite.
Технологический ориентир: Go + Wails, Svelte + TypeScript, Apache ECharts.
Реализована техническая оболочка по спецификации 000: Wails 2.15.0, Go 1.27.2,
Svelte 5/TypeScript 6, Vite 8 и SQLite. Реализован справочник валют и ручные
курсы по спецификации 001; правила представлены в [ADR 0003](decisions/0003-currency-rates.md).
Версии и решения закреплены в [ADR 0001](decisions/0001-app-bootstrap.md).

## Границы ответственности

```text
Svelte UI → Wails bindings / DTO → сценарии приложения → предметная логика
                                       ↓
                              интерфейсы хранения
                                       ↑
                                SQLite-адаптер

Подготовленные данные → Apache ECharts
```

Предметная логика содержит финансовые правила и не зависит от UI и базы данных.
Сценарии приложения координируют операции, валидацию и границы транзакций.
SQLite-адаптер реализует необходимые интерфейсы хранения. Интерфейсы определяются
по потребностям сценариев, без универсального репозитория заранее.
Wails связывает UI с Go через тонкий слой DTO; SQL и финансовые расчёты остаются в Go.

Код группируется по бизнес-модулям внутри `internal/`, а границы слоёв выделяются
по мере необходимости. Модули и API создаются только под согласованные фичи.
Возможные области — операции, инструменты, портфели и оценка; это ориентиры,
а не готовые пакеты или согласованная модель данных.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `AGENTS.md` | Правила архитектуры, точности и проверки изменений |
| `docs/architecture.md` | Общая архитектура и границы модулей |
| `docs/decisions/` | Значимые архитектурные решения (ADR) |
| `docs/features/` | Спецификации фич и критерии приёмки |
| `internal/` | Go-код предметной логики, сценариев и адаптеров |
| `frontend/` | Svelte/TypeScript UI и интеграция ECharts |
| `migrations/` | Версионированные SQL-миграции |

`main.go` запускает Wails и встраивает frontend/dist. `app.go` управляет
инициализацией/закрытием хранилища и предоставляет технический `GetAppInfo`.
`internal/storage/sqlite` управляет общим пулом соединений SQLite и миграциями.
`migrations/embed.go` встраивает SQL-файлы в собранное приложение.
Wails bindings находятся в `frontend/wailsjs` и обновляются при сборке.
Весь Go-код валют сгруппирован в `internal/currency`:

```text
internal/currency/
    domain.go, domain_test.go           — предметные проверки и типы
    service.go, service_test.go         — сценарии и интерфейс хранения
    desktop/api.go, api_test.go         — Wails API и строковые DTO
    sqlite/repository.go, repository_test.go — SQL-запросы и интеграционные тесты
```

Адаптеры зависят от модуля валют, а предметные проверки и сценарии не зависят
от адаптеров. `app.go` подключает компоненты и обеспечивает готовность хранилища
и защиту операций от параллельного закрытия БД; `main.go` регистрирует отдельный
валютный API в Wails. Общий пул принадлежит `internal/storage/sqlite.Store`,
валютный репозиторий получает его без права управлять жизненным циклом.
См. [ADR 0004](decisions/0004-feature-module-layout.md).

## Финансовые данные

Все вычисления выполняются с точными десятичными значениями или целыми числами
с заданным масштабом. Деньги имеют валюту; количество, цена и курс имеют явно
определённую точность. DTO передают эти значения строками. SQLite хранит их как
TEXT или масштабированный INTEGER; выбор фиксируется в ADR до реализации схемы.
REAL и неявные преобразования в дробные числа для финансовых данных запрещены.

Политика округления, метод себестоимости, правила доходности, конвертация валют
и семантика дат определяются спецификациями и тестами. ECharts может использовать
приближённые числа для координат графика, но точные суммы и подписи берутся
из исходных данных. UI не пересчитывает финансовые итоги самостоятельно.

## Хранение

По умолчанию `myinvest.sqlite3` располагается рядом с приложением: рядом с `.app`
на macOS, рядом с исполняемым файлом на Windows/Linux и для отдельного macOS-бинарника.
Используется modernc.org/sqlite 1.58.0, WAL и synchronous=FULL.
`MYINVEST_PORTABLE=0` явно выбирает прежний системный каталог:
на macOS — `~/Library/Application Support/myInvest/myinvest.sqlite3`,
на Windows — `%LOCALAPPDATA%\myInvest\myinvest.sqlite3`, на Linux —
`$XDG_DATA_HOME/myInvest/myinvest.sqlite3` (по умолчанию `~/.local/share`).
Абсолютный `MYINVEST_DATA_DIR` позволяет изолировать тестовые запуски.
`MYINVEST_DATA_DIR` имеет приоритет; отсутствие `MYINVEST_PORTABLE`, пустое значение
и `1` выбирают переносимое хранение. Данные автоматически не переносятся;
при ошибке записи выбранный каталог не меняется. Путь определяется по фактическому
бинарнику после разрешения символических ссылок, независимо от cwd.
См. [ADR 0011](decisions/0011-portable-storage-default.md), уточняющий ADR 0002.
Связанные изменения атомарны; внешние ключи включаются для каждого соединения.
Миграции имеют устойчивый порядок, учёт применённых версий и не переписываются
после применения. Для существующей БД предусматриваются резервная копия
через SQLite VACUUM INTO и безопасное завершение при ошибке.
Версии, имена и SHA-256 записываются в schema_migrations атомарно с SQL;
неизменность истории проверяется перед обновлением. Миграция 0002 создаёт
`currencies` и `currency_rates`: точные курсы TEXT, календарная дата и
упорядоченная пара валют с внешними ключами. При ручном сохранении прямой и
обратный курсы обновляются атомарно. Обратный рассчитывается в Go через
точное целочисленное деление (`math/big.Int`) с округлением half up до 18 знаков
после запятой; прямой курс не округляется. См. [ADR 0005](decisions/0005-inverse-currency-rates.md).

## Как развивать проект

1. Согласовать фичу в `docs/features/`: цель, поведение, входные данные,
   финансовые правила, ошибки и проверяемые критерии приёмки.
2. Зафиксировать значимые решения в `docs/decisions/`: контекст, решение,
   альтернативы и последствия. Использовать последовательные номера файлов.
3. Реализовать минимально нужные модули и миграции, добавить тесты поведения.
4. Проверить Go и фронтенд командами из `AGENTS.md`, обновить документацию.

Запуск и проверки описаны в [README](../README.md). Реализованный
[справочник валют](features/001-currency-directory.md) использует точные строки
без округления для ручного ввода. Обратный курс имеет явно заданное округление;
представление и правила остальных финансовых расчётов выбираются отдельно.

## Портфели

Реализованы просмотр, создание и редактирование по спецификации 002.
`internal/portfolio` содержит типы, проверки названия и календарной даты,
сценарии чтения/создания/редактирования и интерфейс хранения. Подпакеты
`sqlite` и `desktop` реализуют SQL и отдельный Wails `PortfolioAPI`.
Миграция 0003 создаёт `portfolios`: идентификатор INTEGER передаётся в DTO
строкой, `name_key` формируется в Go через TrimSpace/ToLower и защищён UNIQUE.
Валюта ссылается на currencies и при редактировании проверяется в Go; UPDATE
не изменяет её и дополнительно проверяет совпадение в WHERE. Каждое сохранение
выполняется одним атомарным SQL-запросом. Дата хранится и передаётся календарной
строкой без часового пояса. Поля формы получают структурированные ошибки;
ошибки хранения скрывают технические детали. `PortfolioManager.svelte`
отвечает за меню, модальные окна, загрузку, повтор чтения и возврат фокуса.

## Денежные операции

Реализована спецификация 003. `internal/operations` содержит точные суммы,
расчёт остатка и справочного курса, проверки и сценарии журнала. Адаптеры
`sqlite` и `desktop` обеспечивают транзакции и отдельный Wails `CashFlowAPI`.
Миграция 0004 создаёт `cash_flows`; суммы — TEXT, устойчивые идентификаторы
INTEGER с AUTOINCREMENT передаются строками. Остаток выводится из снимка
истории в Go; справочные курсы не участвуют. Арифметика math/big и округление
курса описаны в [ADR 0006](decisions/0006-portfolio-cash-flows.md).
Отрицательный остаток разрешён с предупреждением; дополнительных ограничений
дат нет. `CashFlowManager.svelte` показывает выбор портфеля, остаток, журнал,
формы изменения и подтверждение удаления. После сохранения портфеля список
выбора обновляется. Суммы и курс UI получает строками из Go; устаревшие ответы
чтения и предварительного расчёта курса отбрасываются.

## Сделки и общий журнал

Реализована спецификация 004. `internal/operations` объединяет денежные операции
и сделки, используя единые формулы точных денег и количеств. Wails CashFlowAPI
расширен DTO сделок, предварительным расчётом и справочником активов.
`CashFlowManager.svelte` показывает все четыре вида операций, отдельный тикер,
предупреждения и формы; `AssetManager.svelte` добавляет общий справочник.

Миграция 0005 переносит cash_flows в operations/cash_flow_details с прежними ID
и максимумом AUTOINCREMENT. trade_details содержит точные исходные значения
и среднюю цену; assets — нормализованные уникальные тикеры. Триггеры защищают
вид деталей и неизменность ID/портфеля/вида операции. daily_cash_balances и
daily_asset_balances сохраняют воспроизводимые итоги. Поставляемый FS миграций
добавляет точный Go-шаг пересчёта внутри транзакции миграции.
CRUD обоих видов операций атомарно перестраивает дневную историю портфеля.
Средняя цена округляется half up до 18 знаков; остальные значения сохраняют
точность. См. ADR 0007 и [ADR 0008](decisions/0008-asset-trades-and-daily-balances.md).

## Сплит и обратный сплит акций

[Спецификация 005](features/005-stock-splits.md) расширяет общий журнал
отдельными деталями split. Согласованы применение в начале календарного дня,
точное преобразование количества и отказ при периодическом результате
без компенсации дробей. [ADR 0009](decisions/0009-stock-splits.md) уточняет
порядок ADR 0007 и правила точности. Миграция 0006 расширяет допустимые
виды operations и добавляет split_details, сохраняя историю и верхнюю границу ID.
CRUD пересчитывает все дневные остатки в одной транзакции; периодический
результат любого последующего split откатывает изменение. Предварительный
расчёт Go моделирует всю историю с прежним ID при редактировании. Количества
до/после выводятся из истории; DTO и Svelte передают и отображают точные строки.


## Типы активов

Реализована [спецификация 006](features/006-asset-types.md).
`internal/operations` определяет фиксированный каталог семи типов и проверяет
обязательный выбор при добавлении и смене типа. `CashFlowAPI` передаёт каталог,
строковый `typeCode` и структурированные ошибки. `AssetManager.svelte` использует
общую форму для добавления из меню и сделки, назначения и изменения типа.
Обновление типа сохраняет выбранный в сделке ID.

Миграция 0007 добавляет nullable `assets.type_code` с CHECK допустимых кодов.
Старые записи получают NULL и отображаются как «Тип не указан»; сделки с ними
остаются доступны. Изменение типа атомарно обновляет только общую запись актива,
без изменения сделок и дневных остатков. См. [ADR 0010](decisions/0010-asset-types.md).

## Главный экран и оценка

Реализована [спецификация 007](features/007-main-screen.md).
`internal/valuation` рассчитывает обзор из сохранённых дневных данных;
`sqlite` читает портфели, дневные остатки, типы и курсы в одной транзакции,
`desktop.OverviewAPI` передаёт строковые стоимости, доли и исторические точки.
Чтение обзора не обращается к журналу. Накопительные пополнения в RUB
читаются из `daily_cash_balances.deposits_rub` без конвертации по курсам;
точное построение и неполные старые записи описаны в [ADR 0013](decisions/0013-cumulative-rub-deposits.md). Миграция 0008 добавляет в
`daily_asset_balances` точную рациональную стоимость позиции и ID сделки цены.
Пересчёт операций атомарно сохраняет количества и стоимости; первичное
заполнение выполняется Go-шагом миграции. См. [ADR 0012](decisions/0012-daily-valuation.md).

Обзор оценивает портфели на конец сегодняшней локальной даты по последней
цене сделки своего портфеля с поправкой на сплиты. Отдельные карточки
показывают собственную валюту, совокупные графики — RUB по последнему прямому
курсу не позднее даты оценки. Будущие операции остаются на вкладке «Операции»
и не входят в обзор. ECharts получает подготовленные Go-данные; number
используется только для геометрии. Точные подписи берутся из строковых DTO.

## Анализ портфеля

[Фича 008](features/008-portfolio-analysis.md) расширяет `internal/valuation`
сценарием анализа с текущей оценкой и средней себестоимостью FIFO.
История выбранного портфеля читается до даты оценки в read-only транзакции
через адаптер `operations/sqlite`; обзор сохраняет чтение дневных снимков.
Точные рациональные расчёты выполняются в Go, UI показывает строковые DTO.
Продажи списывают ранние партии покупок, средняя себестоимость равна
себестоимости оставшихся партий / текущему количеству; при нулевом количестве — 0.
Комиссии и дивиденды исключены. Сплиты меняют количества партий, сохраняя
их полную себестоимость. При неполной истории себестоимость недоступна.
См. [ADR 0014](decisions/0014-portfolio-analysis.md).

## Ручные котировки

[Фича 009](features/009-asset-quotes.md) добавляет вкладку «Котировки» с ценами
активов и отдельной таблицей курсов валют. `internal/quotes` проверяет точные
строковые цены, `sqlite` сохраняет их в `asset_quotes` (миграция 0010),
`desktop.QuotesAPI` предоставляет чтение и UPSERT со структурированными ошибками.
Ключ — актив, дата, валюта; цены общие для всех портфелей. Валютный сценарий
читает существующие currency_rates без изменения правил сохранения.
Котировки не участвуют в оценке обзора. См. [ADR 0015](decisions/0015-asset-quotes.md).


### Обновление оценки по котировкам

[ADR 0016](decisions/0016-quote-or-trade-valuation.md) заменяет описанные выше
источники текущей стоимости в обзоре и анализе на последнюю котировку или
сделку на дату оценки. valuation использует общий точный индекс выбора цены,
сведения о split и прямые валютные курсы. Обзор продолжает читать сохранённые
дневные количества и стоимости сделок; дополнительно читает только даты
источников и split, без восстановления истории сделок. Анализ читает историю
и справочные цены согласованно. Средняя цена рассчитывается отдельно
по формуле из раздела «Анализ портфеля».


## Целевое распределение портфеля

Реализованы [спецификация 010](features/010-portfolio-target-allocation.md)
и [ADR 0017](decisions/0017-portfolio-target-allocation.md).
AllocationService в internal/valuation читает согласованный снимок плана,
истории, котировок, курсов и справочника. Предметный расчёт использует точные
рациональные значения и два сценария с целевой долей денег. Выбор цены —
последняя котировка или более поздняя покупка; продажи источником цены этой
фичи не служат. Прежние обзор и анализ сохраняют правила ADR 0016.
Миграция 0011 хранит доли в сотых процента в отдельных таблицах плана и строк;
замена атомарна, generation/revision защищают от устаревшего сохранения.
AllocationAPI передаёт строковые DTO, TargetAllocation.svelte и TargetPie.svelte
показывают редактор, диаграмму и таблицу без расчётов денег в JavaScript.

## Бенчмарки

Реализована [спецификация 011](features/011-benchmarks.md): отдельная вкладка,
справочник независимых индексов/стоимостей и ручная история. `internal/benchmarks`
содержит точные расчёты и сценарии; `sqlite` выполняет атомарный пересчёт цепочки,
`desktop` предоставляет отдельный BenchmarksAPI. Миграция 0012 хранит исходный
способ ввода, введённое значение, стоимость и прирост в TEXT. Правила начального
значения, округления и изменения истории описаны в [ADR 0018](decisions/0018-benchmark-history.md).

Справочник бенчмарков также доступен через меню приложения. Миграция 0014
добавляет необязательный текст `sources`; модуль проверяет HTTP/HTTPS-ссылки,
а отдельный сценарий меняет только источники, без пересчёта истории.

## Дивиденды

[Фича 013](features/013-portfolio-dividends.md) расширяет `internal/operations`
видом `dividend`: положительное фактическое зачисление в валюте портфеля,
необязательный актив и комментарий. `dividend_details` (миграция 0013)
хранит точную сумму TEXT и nullable ссылку на актив. SaveDividend принимает
строковые DTO; журнал поддерживает создание, редактирование и удаление.
Деньги и дневные итоги пересчитываются атомарно, количество, цены и
накопительные пополнения не меняются. См. [ADR 0021](decisions/0021-portfolio-dividends.md).


## Сравнение доходности

[Спецификация 014](features/014-return-comparison.md) расширяет valuation:
ComparisonService читает дневные оценки, внешние потоки и бенчмарки одной
read-only транзакцией, рассчитывает рублёвый TWR и годовые проценты в Go.
ComparisonAPI передаёт строковые DTO, ReturnComparison.svelte показывает
график в начале вкладки «Бенчмарки», выбор инфляции и таблицу. Начальная
привязка и правила дневных потоков — [ADR 0022](decisions/0022-return-comparison.md).

## Финансовый план

Реализована [спецификация 012](features/012-financial-plan.md).
`internal/planning` содержит точный годовой расчёт, сценарии и интерфейс хранения;
адаптеры SQLite/Wails обеспечивают согласованные снимки и строковые DTO.
Миграция 0014 хранит один план на валюту: параметры, точный ручной начальный
капитал и исходный сценарий. Актуальный прогноз пересчитывается по истории
бенчмарка при чтении. Миграция 0013 и её данные сохранены для совместимости;
однозначные старые планы перенесены по валютам. Зависимости планирования
от портфелей, журнала и исторической оценки нет.
`FinancialPlan.svelte` и `PlanChart.svelte` показывают форму, два сценария,
годовую таблицу и подготовленные координаты графика. См. [ADR 0020](decisions/0020-currency-financial-plan.md).
