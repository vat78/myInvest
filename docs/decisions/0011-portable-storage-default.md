# ADR 0011: переносимое хранение по умолчанию

Статус: принято. Дата: 2026-10-14.

## Контекст

Приложение должно создавать `myinvest.sqlite3` рядом с собой без дополнительной
настройки, чтобы приложение и данные можно было переносить одним каталогом.
ADR 0002 уже определяет переносимый путь, но требует `MYINVEST_PORTABLE=1`.

## Решение

Изменить режим по умолчанию из ADR 0001 и ADR 0002: отсутствие
`MYINVEST_PORTABLE`, пустое значение и `1` выбирают переносимый каталог.
Явное `0` сохраняет доступ к прежнему системному каталогу. Иные значения
по-прежнему вызывают ошибку. Абсолютный `MYINVEST_DATA_DIR` имеет высший приоритет.

Путь определяется через `os.Executable()` и `filepath.EvalSymlinks()`, независимо
от cwd. На macOS БД располагается рядом с `.app`, вне пакета: замена приложения
при обновлении не удаляет данные. Для отдельного бинарника на любой платформе
используется его каталог. WAL, sidecar-файлы и `backups/` находятся рядом с БД.

## Последствия

Переносимое хранение работает без переменных окружения. Каталог приложения должен
быть доступен для записи; при ошибке приложение завершает запуск без выбора
другого каталога. Для разработки можно явно задать `MYINVEST_DATA_DIR`.

Существующая БД в системном каталоге автоматически не переносится и не удаляется.
Для продолжения работы с ней можно указать `MYINVEST_PORTABLE=0` либо закрыть
приложение и перенести БД вместе с sidecar-файлами и резервными копиями вручную.
При перемещении приложения пользователь переносит также эти файлы и `backups/`.
Новых зависимостей и изменений схемы не требуется.
