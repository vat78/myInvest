# ADR 0004: организация кода по бизнес-модулям

Статус: принято. Дата: 2026-10-12.

## Контекст

Код валют был распределён между корнем проекта, `internal/currency` и общим
адаптером SQLite. При росте приложения такая структура усложняет поиск кода
фичи и расширяет корневой `App` методами каждой бизнес-возможности.

## Решение

Go-код валют и его тесты находятся под `internal/currency`. В основном пакете
`domain.go` содержит правила и типы, `service.go` — сценарии и интерфейс
хранения. Подпакет `desktop` содержит отдельный Wails API и DTO, подпакет
`sqlite` реализует интерфейс хранения. Предметная логика и сценарии не
импортируют адаптеры. Для новых фич аналогичная структура создаётся при реализации.

Корень проекта отвечает за запуск и подключение компонентов. Валютный API
регистрируется как отдельный объект Wails; bindings переходят с `main/App`
на `desktop/API`. Доступ к сервису передаётся адаптеру через функцию, которая
ожидает инициализацию и удерживает блокировку хранилища на время операции.

`internal/storage/sqlite` сохраняет общие соединения, настройки, резервные
копии и миграции. `Store.DB()` предоставляет подготовленный пул адаптерам;
закрывает его только владелец Store. SQL-миграции остаются в `migrations/`
с прежними версиями и содержимым.

## Последствия

У валют нет предметного кода или DTO в корне проекта. У каждого слоя свои
тесты; интеграционные тесты репозитория открывают временные БД через общий
Store. При изменении места регистрации Wails API bindings нужно регенерировать.
Схема БД, правила точности и пользовательское поведение сохраняются.
