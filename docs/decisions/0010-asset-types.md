# ADR 0010: фиксированные типы активов

Статус: принято. Дата: 2026-10-13.

## Контекст

[Фича 006](../features/006-asset-types.md) добавляет семь допустимых типов
в общий справочник `assets`. Существующие записи имеют только ID и тикер,
на них ссылаются сделки и дневные остатки. Тип не выводится достоверно
из тикера и не участвует в финансовых расчётах.

## Решение

1. Хранить стабильный строковый код, отделённый от английского названия.
   Каталог кодов и названий определён в Go, UI получает его через Wails.
   Новые пакеты и зависимости для каталога не нужны.
2. Добавить следующую миграцию `0007_asset_types.sql`. Она расширяет `assets`
   полем `type_code TEXT NULL`
   с CHECK: NULL либо один из семи кодов спецификации. Пустая строка запрещена.
   Историческая миграция 0005 остаётся неизменной.
3. Существующие строки получают NULL. Это техническое переходное состояние,
   а не дополнительный тип. В DTO оно представлено пустым `typeCode`.
   Добавление и смена типа через сценарии требуют один из семи кодов.
4. Тип меняется отдельным сценарием по устойчивому ID одним атомарным UPDATE.
   Тикер и ID не меняются, отсутствующая запись возвращает предметную ошибку.
   Связи и дневные итоги не перестраиваются: тип не участвует в формулах.
5. Классификация описывает текущее состояние общего справочника.
   Снимки типа в сделках и история классификации пока не сохраняются.
6. При реализации сохранить разделение domain/service, desktop DTO и
   SQLite-адаптера внутри существующего модуля `internal/operations`.
   Wails проверяет форму DTO; Go проверяет допустимость типа;
   SQL находится только в адаптере и миграции.

## Альтернативы

- Отдельная таблица типов и FK: полезна для пользовательского редактирования,
  которого нет в требованиях; добавляет синхронизацию таблицы с кодом.
- Английские названия в БД: связывают сохранённые значения с подписью UI.
- Автоматический тип или общий тип по умолчанию: создаёт ложную классификацию.
- Обязательный NOT NULL сразу: требует выдумать тип старым записям либо
  остановить миграцию до ручного выбора каждого актива.
- Тип в каждой сделке: дублирует свойство справочника и требует правил
  исторической классификации, не входящих в текущую фичу.

## Последствия

Набор типов закрытый; расширение требует изменения Go-каталога и новой миграции
ограничения БД. Данные старой версии сохраняются без предположений о типе.
Сценарии запрещают создание новых неклассифицированных активов, но сама БД
допускает NULL для совместимости со старыми данными.

Смена типа применяется ко всему справочнику во всех портфелях. Будущим отчётам
понадобится явно выбрать текущую или историческую классификацию; этот ADR
определяет только текущую. Никаких изменений правил точности и финансовых
вычислений не вводится.
