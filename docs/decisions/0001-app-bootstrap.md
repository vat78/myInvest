# ADR 0001: оболочка приложения и локальное хранилище

Статус: принято. Дата: 2026-10-12.

## Контекст

Спецификация 000 требует запускаемого desktop-приложения, воспроизводимой сборки
и безопасного обновления SQLite. Бизнес-модель и финансовые типы пока не нужны.

## Решение

- Go 1.27.2, Wails **2.15.0** (стабильная ветка 2), Svelte **5.57.2**,
  TypeScript **6.0.3**, Vite **8.3.4**, `@sveltejs/vite-plugin-svelte` **7.3.1**,
  `svelte-check` **4.7.6**. TypeScript 6 соответствует peer dependency svelte-check;
  TypeScript 7 пока несовместим. Проверены Node **26.3.1**, npm **11.16.0**.
  Прямые зависимости фиксируются без диапазонов; транзитивные — `go.sum` и
  `frontend/package-lock.json`. CLI Wails устанавливается той же версии, что Go-модуль.
- SQLite-драйвер **modernc.org/sqlite 1.58.0**: SQLite без CGO, API `database/sql`.
  CGO и системный компилятор всё равно нужны для самого Wails на macOS.
- Единственный технический адаптер хранения — `internal/storage/sqlite`.
  Он управляет соединениями, резервными копиями и миграциями. Корневой `App`
  управляет жизненным циклом и предоставляет только `GetAppInfo` для UI.
  Готовность Go-вызова ожидает завершения инициализации, включая миграции.
- Путь БД определяется системным каталогом данных, независимо от cwd.
  Для тестовых запусков поддерживается абсолютный `MYINVEST_DATA_DIR`.
- WAL, `synchronous=FULL`, `busy_timeout=5000`, `foreign_keys=ON`.
  Последние три настройки задаются в DSN для **каждого** соединения пула.
  Хранилище закрывается в `OnShutdown`; при ошибке открытия или миграций
  соединения закрываются; после готовности окна (`OnDomReady`) показывается
  диалог с кнопкой «Закрыть», затем приложение завершается.
- Миграции `NNNN_name.sql` идут непрерывно с 0001 и встроены через `go:embed`.
  Первая создаёт только техническую таблицу `schema_migrations`.
  SQL и запись версии/имени/SHA-256/времени UTC выполняются в одной транзакции.
  Изменённая, пропущенная или более новая история вызывает отказ запуска.
  Завершённые ранее миграции сохраняются при ошибке следующей; повторный запуск
  продолжает с первой неприменённой миграции. SQL-файлы не содержат собственных
  BEGIN/COMMIT/ROLLBACK: транзакцией управляет адаптер.
- Если существующая БД требует новых миграций, **до первой из них** выполняется
  параметризованный `VACUUM INTO` в уникальный файл каталога `backups` рядом с БД.
  Это согласованный снимок SQLite с учётом WAL, а не копирование файла БД.
  Ошибка копирования запрещает миграции. Незавершённая копия удаляется;
  исходная БД никогда не удаляется. Готовые копии автоматически не очищаются.
- Ресурсы собранного фронтенда также встроены в executable. ECharts добавляется
  при реализации первого графика; финансовые типы — в спецификации 001.

## Альтернативы и последствия

Wails 3 пока имеет статус beta; выбрана стабильная ветка 2.
`mattn/go-sqlite3` требует CGO для слоя хранения; modernc позволяет тестировать
SQLite независимо от системной C-библиотеки, ценой более крупного бинарника.
Сторонний migration framework пока не нужен: строгий порядок и история покрыты
небольшим адаптером и интеграционными тестами.

`VACUUM INTO` требует дополнительного места и создаёт полную копию перед каждым
обновлением схемы. Миграции выполняются при запуске, до доступа UI к данным;
изменять БД внешними инструментами в это время не следует. Не предусмотрены
автоматический downgrade, восстановление копии поверх пользовательской БД или
массовое удаление копий. При ошибке пользователь получает путь/причину в диалоге.
