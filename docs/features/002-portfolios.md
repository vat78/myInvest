# Портфели: добавление и редактирование

## Цель

Пользователь может просматривать портфели, добавлять новые и редактировать
существующие. Данные сохраняются в локальной SQLite-БД и доступны после
перезапуска приложения.

## Область фичи

- Кнопка с тремя точками справа в верхней панели приложения.
- Всплывающее меню с первым пунктом «Портфели».
- Окно со списком портфелей, добавлением и редактированием.
- Хранение описания портфеля: название, дата открытия и валюта.

Удаление, архивирование, выбор активного портфеля, операции, позиции,
расчёт стоимости и конвертация валют в эту фичу не входят.

## Данные и правила

| Поле | Семантика и правила |
|---|---|
| Идентификатор | Устойчивый внутренний идентификатор; при редактировании не меняется |
| Название | Обязательное, после удаления пробелов по краям не пустое; уникальное без учёта регистра и пробелов по краям |
| Дата открытия | Обязательная календарная дата, вводится пользователем и может редактироваться; хранится как `YYYY-MM-DD` |
| Валюта | Обязательная валюта портфеля; выбирается при создании и не может изменяться |

Под «датой создания» в исходном описании понимается дата открытия портфеля,
а не время добавления записи в приложение. Она не содержит времени или часового
пояса и не преобразуется в UTC. Некорректные календарные даты отклоняются.
Ограничение на будущие даты не вводится.

Название сохраняется с удалёнными пробелами по краям и с исходным регистром.
Для проверки уникальности Go формирует отдельный ключ: удаляет пробелы по краям
через `strings.TrimSpace` и приводит к нижнему регистру через `strings.ToLower`.
Это правило применяется и к кириллице. Внутренние пробелы сохраняются.
Например, « Основной » и «основной» считаются одним названием.

Валюта выбирается из справочника валют приложения. Произвольный текст не
считается выбранной валютой. Создание валют и ввод курсов относятся к отдельной
фиче справочника валют; перед реализацией требуется согласованная модель этого
справочника. Валюта портфеля задаёт валюту будущего представления итогов;
эта фича финансовые итоги не рассчитывает.

## Интерфейс

### Верхняя панель и меню

Справа в верхней панели расположена кнопка «⋯» с доступным названием «Меню».
По нажатию рядом с кнопкой открывается всплывающее меню. Его первый пункт —
«Портфели». Выбор пункта закрывает меню и открывает модальное окно «Портфели».
Меню закрывается при повторном нажатии кнопки, клике вне меню или Escape.

### Список портфелей

В окне отображаются кнопка «Добавить портфель» и таблица с колонками:
«Название», «Дата открытия», «Валюта», «Действия».
В каждой строке есть кнопка «Редактировать» для соответствующего портфеля.
Дата отображается в формате `ДД.ММ.ГГГГ`, валюта — своим кодом.
Порядок строк: дата открытия по убыванию, затем нормализованное название
по возрастанию при одинаковой дате.

При отсутствии записей показывается сообщение «Портфелей пока нет»;
кнопка добавления остаётся доступной. Загрузка и ошибка чтения имеют отдельные
состояния; ошибка не отображается как пустой список. При ошибке доступен повтор
загрузки. Окно можно закрыть кнопкой закрытия или Escape.

### Добавление

Кнопка «Добавить портфель» открывает форму «Добавить портфель»:

- Название — пустое текстовое поле.
- Дата открытия — поле даты, по умолчанию сегодняшняя локальная календарная дата.
- Валюта — выбор из справочника без автоматически выбранного значения.
- Кнопки «Сохранить» и «Отмена».

Сохранение создаёт одну запись. После успешного сохранения форма закрывается,
список обновляется и содержит новый портфель. Повторное нажатие «Сохранить»
во время запроса заблокировано. При ошибке введённые значения сохраняются,
форма остаётся открытой. «Отмена» закрывает форму без записи в БД.

### Редактирование

Кнопка в строке открывает форму «Редактировать портфель», заполненную данными
выбранной записи. Название и дата открытия доступны для изменения.
Валюта отображается только для чтения. Запрет изменения валюты проверяется
также в Go, независимо от ограничений UI.

Сохранение обновляет существующую запись, сохраняя её идентификатор и валюту.
После успеха форма закрывается, список обновляется с учётом нового порядка.
Отмена, блокировка повторного сохранения и поведение при ошибках аналогичны
добавлению. Если запись не найдена, показывается ошибка без создания новой.

Формы поддерживают управление с клавиатуры. При открытии фокус переходит
в форму, при закрытии возвращается к вызвавшей её кнопке.

## Ошибки и валидация

Go проверяет обязательные поля, календарную дату, уникальность названия,
наличие валюты в справочнике и неизменность валюты при редактировании.
UI может предварительно проверять ввод для удобства пользователя.

Ошибки полей показываются рядом с соответствующим полем. Для конфликта названия:
«Портфель с таким названием уже существует». Ошибки хранения показываются
в форме понятным сообщением без SQL и технических деталей.
Неуспешная операция не должна частично изменять данные или обновлять список
как после успешного сохранения.

## Хранение и архитектура

Добавить таблицу `portfolios` новой последовательной SQL-миграцией.
Предусмотреть поля `id`, `name`, `name_key`, `opened_on`, `currency_code`.
Обязательные значения защищены `NOT NULL`, ключ названия — `UNIQUE`,
валюта — внешним ключом на согласованную таблицу справочника валют.
Дата хранится как `TEXT` в формате `YYYY-MM-DD`; её календарная корректность
проверяется в Go. Ограничения БД также отклоняют пустые названия и ключи.

При редактировании проверка уникальности исключает текущую запись;
ограничение `UNIQUE` в БД предотвращает дубликаты при конкурирующих запросах.
Существующая БД мигрируется с резервной копией по общим правилам проекта.
Миграция не создаёт пользовательские портфели автоматически.

Модуль портфелей создаётся в `internal/` при реализации. Сценарии приложения
отвечают за чтение, создание, редактирование и валидацию; SQLite-адаптер —
за SQL и атомарное сохранение. Wails передаёт DTO и вызывает сценарии.
UI не обращается к SQLite напрямую. DTO передают дату и код валюты строками.

## Критерии приёмки

1. Справа в верхней панели есть кнопка с тремя точками; «Портфели» — первый
   пункт открываемого меню.
2. Пункт открывает список с требуемыми колонками, кнопкой добавления и кнопками
   редактирования в каждой строке; пустой список имеет отдельное сообщение.
3. Созданный портфель с заданными названием, датой и валютой появляется
   в списке и сохраняется после перезапуска.
4. Название и дату можно изменить; идентификатор и валюта остаются прежними,
   результат сохраняется после перезапуска.
5. Пустое название, некорректная дата, отсутствующая или неизвестная валюта
   отклоняются без изменения БД.
6. Дубликаты названий отклоняются, включая различия регистра на латинице
   и кириллице и пробелы по краям. Сохранение текущего названия разрешено.
7. Попытка изменить валюту через адаптер отклоняется в Go.
8. Отмена добавления или редактирования не меняет БД; ошибка сохранения
   оставляет форму открытой и сохраняет введённые значения.
9. Дата открытия воспроизводится без сдвига при смене часового пояса.
10. Ошибка чтения отличается от пустого списка; повторная загрузка доступна.

## Проверка при реализации

- Unit-тесты правил названия, дат, обязательных полей и неизменности валюты.
- Интеграционные тесты на временной SQLite-БД: миграция, создание, чтение,
  редактирование, уникальность, внешний ключ и отсутствие частичных изменений
  при ошибках сохранения.
- Проверка UI по сценариям меню, пустого списка, добавления, редактирования,
  отмены, ошибок и управления с клавиатуры.
- `gofmt`, `go test ./...`, `go vet ./...`, проверки и сборка фронтенда
  по существующим скриптам `package.json`, `git diff --check`.
