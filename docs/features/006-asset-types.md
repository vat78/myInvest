# 006. Типы активов в справочнике тикеров

Статус: реализовано. Дата: 2026-10-13.

## Цель и зависимости

Дополнить общий справочник тикеров из [фичи 004](004-portfolio-asset-trades.md)
типом актива. Пользователь выбирает один тип при добавлении тикера и может
назначить или изменить тип существующей записи.

Запрошенный набор из семи типов и английские названия — требования пользователя.
Правила миграции, обязательности выбора и редактирования утверждены
запросом на реализацию. Хранение описано в [ADR 0010](../decisions/0010-asset-types.md).

## Названия и стабильные коды

Названия отображаются на английском в справочнике и списке выбора типа.
Остальные подписи интерфейса остаются русскими. Порядок фиксирован:

| Значение | Английское название | Код для хранения и API |
|---|---|---|
| Биржевые товарные активы | Commodities | `commodities` |
| Облигации | Bonds | `bonds` |
| Фонды денежного рынка | Money Market Funds | `money_market_funds` |
| Акции | Stocks | `stocks` |
| Фонды недвижимости | Real Estate | `real_estate` |
| Ведущие криптовалюты | Cryptocurrencies | `cryptocurrencies` |
| Альт-коины | Altcoins | `altcoins` |

Короткие названия согласованы пользователем. `Commodities` обозначает
категорию биржевых товарных активов, включая ETC и товарные ETF.
`Real Estate` обозначает категорию фондов недвижимости, включая фонды на REIT.
Короткие коды согласованы пользователем; состав категорий сохраняется.

`Cryptocurrencies` — короткая подпись группы ведущих криптовалют.
`Altcoins` пишется одним словом, без дефиса. Рыночное значение altcoin
может включать любую криптовалюту кроме Bitcoin; в приложении две криптогруппы
являются взаимоисключающими ручными категориями. Ведущая криптовалюта получает
`Cryptocurrencies`, остальные пользователь относит к `Altcoins`.
Приложение не определяет состав групп по тикеру, рейтингу или капитализации.

Источники терминологии:

- [London Stock Exchange: ETCs and ETNs](https://www.londonstockexchange.com/raise-finance/etps/etcs-and-etns).
- [Investor.gov: Investment Options](https://www.investor.gov/introduction-investing/investing-basics/save-and-invest/learn-about-investment-options) — Stocks, Bonds, Money Market Funds.
- [Investor.gov: REIT](https://www.investor.gov/introduction-investing/investing-basics/glossary/real-estate-investment-trust-reit) — отдельное понятие для недвижимости.

## Правила справочника

- Один тикер имеет ровно один тип из списка. Пользовательские типы и несколько
  типов на один тикер не поддерживаются.
- Новый тикер требует явного выбора типа; по умолчанию тип не выбран.
- Тикер сохраняет прежние нормализацию, уникальность во всём приложении и ID.
  Добавление того же тикера с другим типом остаётся ошибкой дубликата.
- В существующих записях после миграции тип отсутствует. UI показывает
  «Тип не указан»; это состояние старых данных, а не восьмой допустимый тип.
  Приложение не угадывает тип и не блокирует сделки с такими активами.
- Для старой записи можно назначить тип, для классифицированной — сменить
  его на другой допустимый. Сброс в незаданный тип через API/UI запрещён.
- Тип — текущая характеристика общей записи справочника во всех портфелях.
  История смены типа и снимок типа на дату сделки не ведутся.
- Смена типа сохраняет ID, тикер и ссылки сделок; финансовые результаты
  и дневные остатки не изменяются и не требуют пересчёта.

## Интерфейс

В окне «Активы» список содержит тикер, тип и действие «Изменить тип».
Порядок тикеров сохраняется. Форма добавления содержит поля «Новый тикер»
и «Тип актива»; select показывает семь английских названий в указанном порядке
и пустую подсказку «Выберите тип». После успешного добавления оба поля очищаются.

Редактирование типа открывает форму с неизменяемым тикером, выбором типа,
кнопками «Сохранить» и «Отмена». Для старой записи выбор пустой, для остальных
показывается текущий тип. Отмена ничего не сохраняет.

Добавление актива из формы сделки использует ту же форму с обязательным типом.
Созданный актив доступен для выбора в сделке. Назначение типа существующему
активу обновляет справочник без сброса выбранного в сделке ID.
Тип не добавляется как самостоятельное поле сделки или колонка журнала.

Ошибки выбора выводятся рядом с полем «Тип актива». Пустой код при добавлении
или изменении отклоняется с «Выберите тип актива», неизвестный — с
«Недопустимый тип актива». Несуществующий ID при изменении сообщает
«Актив не найден». Ошибка хранения не раскрывает SQL и технические детали.
При ошибке введённые значения сохраняются для повторной попытки.

Во время сохранения повторная отправка и закрытие формы блокируются.
Чтение имеет состояния загрузки, ошибки и повтора; устаревшие ответы
игнорируются. Select и действия доступны с клавиатуры, ошибки связаны
с полем, после закрытия фокус возвращается к открывшему элементу.

## Данные и границы реализации

Расширить `Asset` и `AssetDTO` полем `TypeCode`; в JSON — `typeCode`.
Для старых неклассифицированных записей DTO содержит пустую строку,
SQLite — NULL. Допустимые коды проверяются в Go и ограничением SQLite.
Идентификаторы по-прежнему передаются строками.

В существующем `internal/operations` добавить тип и проверки кода,
сценарий смены типа и каталог семи пар код/название. Каталог передаётся UI
через `ListAssetTypes()` существующего `CashFlowAPI`; порядок задаёт Go.
Предлагаемый DTO каталога: `code`, `name` (строки).

`AddAsset` принимает DTO `{ticker, typeCode}` вместо отдельного тикера.
`UpdateAssetType` принимает DTO `{id, typeCode}` и возвращает обновлённый
`AssetDTO`, ошибки полей и общее сообщение по существующему шаблону.
`ListAssets` возвращает расширенный DTO. Wails bindings и вызывающий UI
обновляются совместно; расчёты и DTO сделок не меняются.

Миграция добавляет поле без изменения применённых миграций и без
классификации существующих данных. Используется штатная резервная копия
существующей БД и транзакционное применение миграции.

## Критерии приёмки

1. Каталог содержит ровно семь кодов и английских названий из таблицы,
   в фиксированном порядке; дополнительные варианты отсутствуют.
2. Каждый тип можно выбрать при добавлении, он сохраняется после перезапуска.
3. Пустой или неизвестный тип отклоняется Go; дубликат нормализованного тикера
   отклоняется независимо от типа. Ошибка не создаёт запись.
4. Миграция сохраняет тикеры, ID, сделки и остатки; старые записи отображаются
   с «Тип не указан» и доступны для новых и существующих сделок.
5. Старому активу можно назначить тип, существующему — изменить.
   После перезапуска виден новый тип; ID и финансовые результаты прежние.
6. Отмена и ошибки не меняют сохранённый тип. Несуществующий ID не создаёт
   актив; пустой код не снимает уже назначенную классификацию.
7. Ограничение БД отклоняет неизвестные коды и пустую строку;
   NULL поддерживается для перенесённых данных.
8. Добавление из сделки требует тип и позволяет выбрать созданный актив;
   обновление справочника не теряет выбор существующего актива.
9. Формы доступны с клавиатуры; обработаны загрузка, повтор, ошибки полей,
   устаревшие ответы и повторная отправка.

## Проверка при реализации

- Unit-тесты каталога, проверки всех кодов, пустого и неизвестного кода,
  обязательности типа и независимой уникальности тикера.
- Интеграционные тесты временной SQLite-БД: перенос данных 0005, CHECK,
  назначение и смена типа, отсутствующий ID, сохранность связей и остатков,
  откат при ошибке. Рабочая БД пользователя не используется.
- Проверка DTO и UI: список, добавление обоими путями, редактирование,
  старые записи, ошибки и сохранение выбора в сделке.
- `gofmt`, `go test ./...`, `go vet ./...`, проверки/тесты/сборка фронтенда
  по существующим скриптам и `git diff --check`.

## Вне области фичи

Группировка и фильтрация, новые финансовые расчёты, графики по типам,
историческая классификация, автоматическое определение типа, рыночные данные,
переименование и удаление тикеров, новые типы и отдельный редактируемый
справочник типов.
