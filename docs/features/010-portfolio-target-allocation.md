# 010. Целевое распределение активов портфеля

Статус: реализовано. Дата: 2026-10-14.

## Цель и зависимости

Ниже текущих данных вкладки «Анализ» выбранного портфеля разместить круговую
диаграмму целевого распределения и таблицу сравнения с двумя сценариями:
покупки только на существующие свободные деньги и ребалансировка с продажами.
Это расчётный план; операции в журнале пользователь оформляет отдельно.

Зависимости — [анализ 008](008-portfolio-analysis.md),
[котировки 009](009-asset-quotes.md) и
[ADR 0016](../decisions/0016-quote-or-trade-valuation.md).
Фича использует имеющиеся
котировки и валютные курсы; новую форму ввода цен создавать не требуется.
Хранение добавлено следующей миграцией 0011.

Подтверждено пользователем: деньги — отдельная целевая доля; расчётная цена —
последняя котировка либо цена последней покупки, если покупка позже котировки.
Запрос на реализацию принимает предложенные ниже правила первой версии.

## Задание цели

Для каждого портфеля хранить один текущий план с долями отдельных активов,
привязанными к устойчивым ID общего справочника. Доли не глобальны и не зависят
от типа актива. Один актив может иметь разные цели в разных портфелях.
Целевые количества и суммы не задаются: они выводятся из долей, стоимости
портфеля и расчётных цен. Это сохраняет смысл цели после пополнений и сплитов.

Кнопка «Задать распределение» / «Изменить распределение» открывает форму:
актив, целевая доля в процентах, добавление строки из справочника, удаление строки.
Можно добавить актив, которым портфель пока не владеет. Дубликаты запрещены.
Ввод процентов точный, с точкой или запятой, от 0 до 100 включительно;
точность — до двух дробных знаков. Сумма долей активов и денег
должна быть ровно 100%.
Показывать введённый итог и недостающую/избыточную долю из Go; автоматически
нормализовать проценты или присваивать последней строке остаток нельзя.

Позиция без строки плана имеет цель 0%; отдельная строка с 0% разрешена.
Удаление строки означает цель 0%, а не запрет продажи. Изменение плана не
меняет сделки. Отсутствие плана отличается от плана с нулевыми целями:
план без активов допустим при доле денег 100%; есть отдельное действие «Удалить план».
Создание, полная замена и удаление плана атомарны. Отмена и ошибки сохраняют
прежний план, ошибки формы сохраняют введённые значения для исправления.

Деньги имеют отдельное обязательное поле доли в форме (допустимо 0%).
Сумма долей денег и активов — ровно 100%. Валюта денег совпадает с валютой
портфеля; деньги не являются записью справочника активов. В диаграмме это
отдельный сектор «Деньги». Целевая доля задаёт резерв, а не новое пополнение.

## Представление в анализе

Блок имеет заголовок «Целевое распределение», дату, валюту и источник цены.
Без плана — пояснение и кнопка настройки, без выдуманной диаграммы.
Слева диаграмма сохранённых положительных целевых долей, справа таблица.
Диаграмма показывает намерение и остаётся доступной при неполной оценке;
расчётные столбцы в этом случае показывают причину недоступности.

Строки таблицы — объединение текущих ненулевых позиций и всех строк плана,
включая ещё не купленные и явно заданные с нулевой долей. Порядок по тикеру,
затем отдельная строка «Деньги»: текущая и целевая сумма, доля и изменения
денег по сценариям. Количество для денег не применяется и показывается «—».

| Столбец | Содержание |
|---|---|
| Актив | Тикер, отсутствие в плане означает цель 0% |
| Сейчас, количество | Точный текущий остаток |
| Сейчас, стоимость | Остаток × расчётная цена |
| Целевая доля | Сохранённый процент |
| Целевая стоимость | Доля от активов вместе со свободными деньгами |
| Целевое количество | Целевая стоимость / расчётная цена |
| Изменение без продаж | Только покупка: количество и сумма в одной ячейке |
| Изменение с продажами | Покупка со знаком +, продажа со знаком −; количество и сумма |

Над таблицей показать стоимость активов, свободные деньги и суммарную базу
цели. Для каждого сценария показать остаток денег и пояснение достижимости.
Целевое количество общее, а изменения без продаж могут не довести до него.
Нулевая целевая доля и нулевое изменение отображаются как 0, отсутствие
цены или невозможность расчёта — как «—» с причиной.

На узком окне таблица под диаграммой, с собственной горизонтальной прокруткой.
Подписи и данные доступны текстом и с клавиатуры. После сохранения обновляется
только актуальный выбранный портфель; устаревший ответ не меняет новый выбор.
При смене портфеля несохранённый ввод не переносится в другой портфель;
перед потерей введённых изменений требуется явный выбор сохранить/отбросить.
Ошибка чтения не трактуется как отсутствие плана. Сохранение блокирует повторную
отправку; параллельное изменение плана обнаруживается по версии, без потери ввода.
Обновление операций, котировок, валютных курсов, наступление новой даты
и возврат фокуса обновляют расчёт.

## Исходные данные и точность

Расчёт на конец сегодняшней локальной календарной даты, будущие операции
не участвуют. Количества учитывают покупки, продажи и split в порядке фичи 008.
Денежный остаток учитывает пополнения, выводы, покупки, продажи и их расходы.
Итоговые цены и суммы — в неизменяемой валюте выбранного портфеля.
Котировка другой валюты переводится по последнему прямому курсу в валюту
портфеля не позднее даты расчёта, как в ADR 0016. Общая оценка в RUB не участвует.

Из источников не позднее даты расчёта выбрать последнюю общую котировку актива
или последнюю покупку этого актива в выбранном портфеле: более поздняя исходная
дата побеждает. При равной дате приоритет котировки, как в ADR 0016: покупка заменяет
котировку только при строго более поздней дате.
Покупки одной даты сравнивать по числовому ID, брать наибольший.
Продажа меняет остатки, но не становится источником цены этой фичи.
Это локальное отличие от текущего ADR 0016, где сравниваются покупки и продажи;
правила уже реализованных обзора и анализа этим проектом не меняются.
Показывать источник, его исходную дату, исходную валюту, курс и дату курса.

Разрешение котировок одной даты, конвертация и поправки split соответствуют
ADR 0016: предпочесть валюту портфеля, иначе первый код валюты по алфавиту;
отсутствие курса не заменять переходом к более раннему источнику. Котировка
корректируется на split строго после её даты, покупка — на последующие split
в порядке операций; split не делает исходную дату цены более свежей.
Использовать точные внутренние цены до округления, не подписи DTO анализа.
Цены условные: расчёт не является готовой биржевой заявкой.

Новый целевой актив без истории покупок получает цену из общего справочника
котировок. Если нет ни допустимой котировки, ни покупки, положительная цель
в деньгах доступна при полной оценке текущих позиций, но целевое количество
и полные сценарии недоступны. Показать причину и переход к существующей
вкладке «Котировки»; молча исключать строку и перераспределять её долю нельзя.
Отсутствующий прямой курс также означает неполную оценку. Нулевая цена для
деления непригодна. Актив с целью 0% и количеством 0 цены не требует.

Финансовая арифметика — Go math/big.Rat; строки в DTO и TEXT/INTEGER в SQLite.
Доли хранятся целым числом сотых процента (100% = 10000), не REAL.
Точные промежуточные результаты не округляются. Вывод:
деньги — два знака half up, расчётное количество — до 18 знаков half up
с отметкой приближённости при округлении; текущий остаток остаётся точным.
Малое ненулевое изменение нельзя показывать как точный ноль.
Отображённое округлённое количество не используется для расчёта суммы.
Это теоретические дробные количества: лоты, шаги количества, ограничения биржи,
комиссии будущих сделок и налоги в первой версии не моделируются.
Фактические расходы прошлого уже учтены в свободных деньгах.

## Формулы двух сценариев

Для каждой строки: q_i — текущий остаток, p_i — положительная расчётная цена,
w_i — целевая доля от 0 до 1. C — текущие деньги; V_i = q_i × p_i.
Общая база T = C + ΣV_i. Целевая стоимость A_i = T × w_i,
целевое количество Q_i = A_i / p_i. У незаданных активов w_i = 0.
w_cash — доля денег, w_cash + Σw_i = 1. Целевой резерв R = T × w_cash.
Процент относится ко всей базе T, а не только к стоимости ценных бумаг.
Оба сценария используют одни и те же цены, базу и цели, без новых пополнений.

### Только свободные деньги

Продаж нет. Дефицит d_i = max(A_i − V_i, 0), D = Σd_i.
Доступный бюджет F = max(C − R, 0), целевой резерв не расходуется.
Покупки распределяют бюджет B = min(F, D) пропорционально дефицитам:
b_i = B × d_i / D, изменение количества = b_i / p_i.
При F = 0 или D = 0 все покупки равны 0. Остаток = C − Σb_i.
Если C < R, без продаж резерв недостижим: покупок нет, показывается нехватка
R − C. Это не запрещает сохранение плана и не создаёт фиктивного пополнения.

При избытке отдельного актива другие позиции могут остаться ниже цели:
показывать это явно. Это выбранная эвристика, а не единственный оптимальный
алгоритм; альтернативу выравнивания долей до общего уровня нужно согласовать
отдельно. При валидных неотрицательных данных D ≥ max(C − R, 0),
поэтому распределяется весь остаток сверх резерва. Изменение строки денег
равно −Σb_i, итог денег = C − Σb_i; при C ≥ R он равен R.

### С продажей избыточных активов

Изменение стоимости x_i = A_i − V_i, количества Δq_i = Q_i − q_i.
Отрицательные значения означают продажу, положительные — покупку.
При q_i ≥ 0, C ≥ 0 и w_cash + Σw_i = 1 продажи не превышают текущие количества,
Σx_i = C − R, теоретический денежный остаток после сделок равен R.
Изменение строки денег равно R − C = −Σx_i; при недостатке резерва продажи
могут превышать покупки. Доля денег 100% означает продажу всех позиций.
Суммы считаются из точных значений до вывода; округлённые строки могут
не сходиться на копейку. Самостоятельных операций этот расчёт не создаёт.

### Пример для проверки

A: 6 единиц по 100 = 600; B: 3 единицы по 100 = 300; деньги 300.
Цель A/B/деньги = 40%/40%/20%, T = 1200. Целевые стоимости 480/480,
количества 4,8/4,8; резерв R = 240.
Без продаж: бюджет 60, купить 0,6 B на 60; A не менять. Итог 600/360/240,
цель активов ещё не достигнута, денежный резерв сохранён.
С продажами: продать 1,2 A на 120 и купить 1,8 B на 180.
Итог 480/480/240 — целевые доли достигнуты.

При тех же позициях и деньгах 100 база T = 1000, цель 400/400/200.
Без продаж: покупок нет, резерву не хватает 100.
С продажами: продать 2 A на 200 и купить 1 B на 100,
итог 400/400/200, резерв восстановлен из продаж.

## Неполные и отрицательные данные

Отрицательные деньги/позиции допустимы в учёте и не блокируют сохранение цели.
Оба сценария отключаются с предупреждением о полноте истории,
сохраняя текущие остатки и целевую диаграмму; поддержка долга/коротких позиций
требует отдельной модели. При отсутствующей оценке текущей ненулевой позиции
общая база и производные цели недоступны для всех строк.
При пустом портфеле и C = 0 база и целевые стоимости равны 0;
покупки/продажи равны 0, неизвестная цена не препятствует выводу нулей.
При C > 0 и отсутствии позиций расчёт возможен только с доступными ценами
целевых активов; котировки общие, покупки чужого портфеля не участвуют.
Если доля денег 100%, отсутствующие цены нулевых позиций не мешают расчёту.

## Хранение и границы

См. [ADR 0017](../decisions/0017-portfolio-target-allocation.md).
Хранятся только намерения: план с долей денег и строки процентов активов.
Количества, стоимости,
рекомендации и диаграмма рассчитываются при чтении. Один согласованный снимок
для плана, операций/остатков, справочника, котировок, split и курсов
предотвращает смешение обновлений.
Сценарий целей выделен в internal/valuation отдельным AllocationService, SQLite — адаптер,
Wails проверяет DTO и вызывает сценарий, Svelte только вводит и отображает.
Миграция 0011 создаёт план и строки долей. AllocationAPI предоставляет
чтение, предварительную проверку, сохранение и удаление; TargetAllocation.svelte
и TargetPie.svelte отображают форму, диаграмму и таблицу. Новых зависимостей нет.

## Критерии приёмки и проверки

1. Планы разных портфелей независимы и сохраняются после перезапуска;
   можно задать актив без текущей позиции. Смена типа не меняет цель.
2. Go отклоняет неизвестный ID, дубликаты, неверный формат, выход за диапазон,
   лишнюю точность и итог, отличный от 100%, без частичного сохранения.
3. Создание/замена/удаление атомарны; ошибка любой строки откатывает всё.
   Версия предотвращает потерю конкурирующего изменения; FK и UNIQUE проверены
   интеграционными тестами на временной БД. Миграция сохраняет историю и остатки.
4. Таблица включает объединение позиций и плана; актив вне плана имеет цель 0%,
   а сценарий с продажами предлагает его полное закрытие.
5. Оба примера с резервом воспроизводятся точно. Дополнительные табличные тесты:
   несколько дефицитов, нулевые деньги, уже достигнутая цель, весь бюджет
   в деньгах, доля денег 0%/100%, деньги ниже/на уровне/выше резерва,
   одна доля актива 100%, явные 0%, дроби и периодическое деление.
6. Без продаж покупки не превышают max(C − R, 0), продаж нет;
   с продажами выполняются Σx_i = C − R, итог денег = R, позиции неотрицательны.
   Сумма долей денег и активов при сохранении ровно 100%.
7. Split/обратный split меняет количества и цены взаимно обратно, но сохраняет
   целевые доли и стоимости; будущие операции исключены, портфели не смешиваются.
8. Пропущенная/нулевая цена, отрицательные остатки, пустой портфель и малые
   ненулевые значения показываются согласно правилам выше, без скрытых нулей.
9. Проверены более свежая котировка, более свежая покупка, их одинаковая дата,
   несколько покупок одного дня, новая продажа (не заменяет цену), чужой портфель,
   будущие источники, котировки нескольких валют и отсутствие прямого курса.
   Обновление котировки/курса обновляет рекомендации.
10. UI покрывает настройку/отмену, ошибки/повтор, смену портфеля, устаревшие
   ответы и сохранение с конфликтом версии; диаграмма соответствует точным долям.
11. Проверки: gofmt, go test ./..., go vet ./..., существующие скрипты
    проверки/тестов/сборки фронтенда, сборка Wails и git diff --check.

## Принятые границы первой версии

Цели задаются по отдельным активам и деньгам с шагом 0,01%; хранится один
текущий план без календарной истории целей. Покупки без продаж распределяются
пропорционально дефицитам. Количества теоретические, дробные, с выводом до
18 знаков; будущие комиссии, налоги и биржевые лоты не моделируются.

История целевых стратегий, группы типов, автоматическое исполнение, загрузка
котировок из внешних источников, налоговая оптимизация и подбор дополнительных
пополнений вне проекта. Существующие ручные котировки входят в расчёт.
