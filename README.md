# myInvest

Локальное desktop-приложение для учёта инвестиций: Go, Wails, SQLite и
Svelte/TypeScript. Реализованы техническая оболочка по спецификации
[000](docs/features/000-app-bootstrap.md) и справочник валют с ручными курсами
по [001](docs/features/001-currency-directory.md).

Вверху слева — локальная дата и сегодняшний USD/RUB либо красное `???`.
Нажмите на курс, выберите дату и пару валют и введите положительный курс
с точкой или запятой. Неизвестную валюту добавьте кнопкой «Добавить»;
справочник изначально содержит USD и RUB. Существующий курс подставляется
для редактирования, повторное сохранение заменяет его. Дробные знаки
прямого курса сохраняются точно. При сохранении автоматически обновляется и
обратная пара на ту же дату (до 18 знаков после запятой, половина округляется вверх).
Сохранение сегодняшнего RUB/USD также обновляет USD/RUB на главном экране.
Курсы за другие даты не подставляются. Старые записи обновляются только
при явном сохранении; подробности — [ADR 0005](docs/decisions/0005-inverse-currency-rates.md).

## Среда

Закреплены Go 1.27.2 и Wails 2.15.0; версии фронтенда указаны в
`frontend/package.json`, транзитивные зависимости — в lock-файлах.
Использовались Node 26.3.1 и npm 11.16.0. Vite/plugin требуют Node
20.19+, 22.12+ либо 24+; для воспроизведения используйте проверенные версии.

На macOS нужны Xcode Command Line Tools (`xcode-select --install`).
На Windows нужны компилятор/зависимости Wails и WebView2; на Linux — GCC,
GTK3 и WebKitGTK. Точные платформенные требования:
[документация Wails](https://wails.io/docs/gettingstarted/installation/).
Проверенная ОС — **macOS 27.0.1, Apple Silicon (ARM64)**.
Windows, Linux и более ранние версии macOS в этой задаче не проверялись.
Cross compilation desktop-приложения между ОС не настроена.

## Установка и разработка

Из корня чистого checkout:

```sh
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
# Добавьте каталог `go env GOPATH`/bin в PATH.
go mod download
npm --prefix frontend ci
wails dev
```

`wails dev` запускает Vite и desktop-окно с Go backend. Простое `npm run dev`
запускает только фронтенд: вызовы Go работают внутри Wails.
Bindings в `frontend/wailsjs` генерирует Wails; они хранятся в Git, чтобы
проверка фронтенда была доступна после `npm ci` без генерации.

## Сборка

```sh
wails build
```

На macOS результат — `build/bin/myInvest.app`, открывается через
`open build/bin/myInvest.app`. На Windows/Linux результат находится в
`build/bin/`. Бинарник содержит ресурсы UI и SQL-миграции и не требует checkout.
Сборка локальная, без подписи, notarization и публикации.

## Данные и обновления

Приложение по умолчанию полностью переносимое: `myinvest.sqlite3` создаётся
автоматически рядом с приложением. Переменные окружения для этого не нужны;
cwd не влияет на путь:

| ОС | Путь |
|---|---|
| macOS (.app) | Рядом с `myInvest.app`, вне пакета |
| Windows / Linux / отдельный macOS-бинарник | Рядом с исполняемым файлом |

Для изолированного запуска можно указать **абсолютный** каталог:

```sh
MYINVEST_DATA_DIR=/tmp/myinvest-smoke wails dev
```

У release-бинарника действует тот же параметр окружения. Не подменяйте им
каталог рабочей БД для тестов. WAL и sidecar-файлы управляются SQLite.
Соединения закрываются при выходе; база при повторном запуске сохраняется.

Отсутствие `MYINVEST_PORTABLE`, пустое значение и `1` выбирают переносимое хранение.
При необходимости `MYINVEST_PORTABLE=0` явно возвращает системный каталог:
на macOS — `~/Library/Application Support/myInvest`, на Windows —
`%LOCALAPPDATA%\myInvest`, на Linux — `$XDG_DATA_HOME/myInvest`
(по умолчанию `~/.local/share/myInvest`). Иные значения вызывают ошибку запуска.
`MYINVEST_DATA_DIR` имеет приоритет над переносимым режимом. Символические ссылки
разрешаются: используется каталог фактического бинарника. При `wails dev` это
каталог сгенерированного приложения; для разработки удобнее `MYINVEST_DATA_DIR`.
Каталог должен разрешать запись БД, WAL и резервных копий; при ошибке приложение
покажет сообщение и завершится без перехода в другой каталог. Существующая БД
автоматически не переносится: после обновления приложение использует БД рядом
с собой, а прежняя БД в системном каталоге остаётся на месте. Для ручного переноса
закройте приложение и сохраните
исходную БД вместе с имеющимися sidecar-файлами. При переносе приложения переносите
также БД, её sidecar-файлы и `backups/`.

Новые миграции добавляются как `migrations/0003_name.sql`, затем 0004 и т.д.
Применённые файлы не редактируются. Миграции не содержат управления транзакциями:
адаптер атомарно выполняет файл и записывает версию. Начальная миграция создаёт
только `schema_migrations`. SHA-256 позволяет обнаружить изменение истории;
запуск старой версии приложения с более новой схемой запрещён.

Перед обновлением существующей БД создаётся согласованная копия через
`VACUUM INTO` в `backups/myinvest-<UTC>-<случайный суффикс>.sqlite3` рядом с БД.
Копия включает данные из WAL. Ошибка копирования останавливает обновление.
Ошибка миграции откатывает только эту миграцию вместе с записью её версии;
ранее завершённые миграции сохраняются. Исходная БД не удаляется и не сбрасывается.
При ошибке инициализации приложение показывает сообщение и закрывается.
Копии не удаляются автоматически; восстановление выполняется отдельно,
при закрытом приложении и после сохранения исходных файлов.

## Проверки

```sh
npm --prefix frontend ci
npm --prefix frontend run check
npm --prefix frontend test
npm --prefix frontend run build
# dist нужен go:embed; в чистом checkout сначала соберите фронтенд.
gofmt -w *.go internal/currency/*.go internal/currency/desktop/*.go internal/currency/sqlite/*.go internal/storage/sqlite/*.go migrations/embed.go
go test ./...
go vet ./...
wails build
```

Интеграционные тесты используют только временные SQLite-БД: повторный запуск,
порядок миграций, откат SQL и записи версии, внешние ключи на разных соединениях,
резервная копия с WAL, блокировка миграций при ошибке копирования, несовместимая
история и сохранение повреждённого файла. UI проверяется через реальное окно Wails;
frontend-тест проверяет локальную календарную дату на границе полуночи, года
и в разных часовых поясах средствами встроенного Node test runner.
Тесты валют проверяют точные строки,
валидацию DTO, независимость дат и направлений пары, UPSERT, перезапуск,
ограничения схемы, резервную копию при обновлении и откат миграции 0002.

Детали решений: [ADR 0001](docs/decisions/0001-app-bootstrap.md),
[ADR 0003](docs/decisions/0003-currency-rates.md).
Организация Go-кода валют и адаптеров: [ADR 0004](docs/decisions/0004-feature-module-layout.md).

## Денежные операции портфеля

На главном экране выберите портфель (создать его можно через меню «Портфели»).
«Пополнить» и «Вывести» записывают фактические денежные потоки. При отличии
валют введите исходную сумму и сумму зачисления/списания в валюте портфеля;
курс справочника не нужен. Суммы и остаток сохраняют всю точность ввода,
справочный курс вычисляется Go и округляется до 4 знаков half up.
Журнал поддерживает редактирование и удаление с подтверждением. Отрицательный
остаток разрешён с предупреждением; будущие даты и даты до открытия разрешены.
Подробности: [спецификация 003](docs/features/003-portfolio-cash-flows.md) и
[ADR 0006](docs/decisions/0006-portfolio-cash-flows.md).

Проверка реализации 003 (2026-10-13): `gofmt`, `go test ./...`, `go vet ./...`,
frontend `check` без предупреждений, 20 frontend-тестов, `build` и
`wails build -nosyncgomod`. Тесты проверяют точную арифметику, округление курса,
изолированность портфелей, миграцию с копией, откат, перезапуск, ошибки,
повторные сохранения и устаревшие ответы. В отдельном release-окне на временной
БД проверены создание портфеля, пополнение `1000 USD / 94500 RUB`, вывод
`500 USD / 48000 RUB` с остатком `46500 RUB`, редактирование до отрицательного
остатка с предупреждением, заполненные формы, подтверждение удаления и его
отмена через Escape с возвратом фокуса. Сохранение через Enter работает.

## Сделки и общий журнал операций

Фича [004](docs/features/004-portfolio-asset-trades.md) добавляет покупки и продажи.
В меню «Активы» создавайте тикеры; новый актив можно добавить также из формы
сделки, после чего он выбирается автоматически. «Купить» и «Продать» принимают
количество, сумму без расходов и дополнительные расходы в валюте портфеля.
Средняя цена рассчитывается Go без расходов и округляется half up до 18 знаков;
округление явно отмечено. Исходные суммы и количества сохраняются точно.

Все четыре типа видны в общем журнале с отдельным тикером и изменением денег.
Продажа сверх исторического количества сохраняется с предупреждением,
включая предупреждения после изменения ранних операций. Дневные остатки
сохраняются для будущих фич; список позиций и графики пока не показываются.
Миграция 0005 переносит старые денежные операции с прежними ID и создаёт
точные дневные итоги; перед обновлением существующей БД выполняется backup.
Правила реализации — [ADR 0008](docs/decisions/0008-asset-trades-and-daily-balances.md).

Проверка реализации 004 (2026-10-13): `gofmt`, `go test ./...`, `go vet ./...`,
frontend `check` без ошибок и предупреждений, 29 frontend-тестов, `build` и

## Сплит и обратный сплит акций

Действие «Сплит» в выбранном портфеле принимает дату, актив и пропорцию
положительными целыми числами: например, 1 → 10 или 10 → 1. Предварительный
расчёт показывает точное количество до и после. Сплит применяется в начале
дня; сделки этой даты вводятся в новых единицах. Деньги и исходные сделки
не изменяются. В журнале сплиты идут первыми внутри даты.

Конечные дроби сохраняются без округления, включая дроби длиннее 18 знаков.
Периодический результат отклоняет запись, изменение или удаление целиком,
с указанием тикера, даты и пропорции проблемного сплита. Компенсация дробей
не выполняется. Миграция 0006 сохраняет прежние операции, детали и ID;
перед обновлением существующей БД создаётся резервная копия.
Правила — [спецификация 005](docs/features/005-stock-splits.md)
и [ADR 0009](docs/decisions/0009-stock-splits.md).

Проверка реализации 005 (2026-10-13): `gofmt`, `go test ./...`,
`go vet ./...`, `go test -race ./...`, frontend `check` без предупреждений,
33 frontend-теста, `build` и `wails build -nosyncgomod`. Тесты покрывают
точность, порядок, CRUD, preview, откат исторических правок и удаления,
миграцию 0005 → 0006 с backup, ограничения, перезапуск и конкуренцию.

с сохранением ввода, сохранение обратного сплита 10 → 1 через Enter
и журнал с количеством 12 → 1,2 и неизменным денежным остатком.


## Типы активов

В справочнике «Активы» новый тикер требует выбора одного из семи типов.
«Изменить тип» позволяет классифицировать старый тикер или изменить его тип;
ID, сделки и финансовые итоги сохраняются. Старые записи после миграции
показывают «Тип не указан» и остаются доступны для сделок.
Добавление из формы сделки использует ту же форму с обязательным выбором типа.
См. [спецификацию 006](docs/features/006-asset-types.md) и
[ADR 0010](docs/decisions/0010-asset-types.md).
